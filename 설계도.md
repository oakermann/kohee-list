# Kohee List blueprint

<!-- parts: functions/api/*.js server/*.js site/*.html site/assets/*.js site/assets/*.css schema.sql scripts/*.mjs wrangler.toml -->

Cafe curation site https://kohee.pages.dev — no accounts ('my reports' via a random browser token), the admin publishes. Source context = `docs/KOHEE_MASTER_CONTEXT.md`.

## Big picture

```
 browser
   site/index.html(list·near me·search·cafe sheet) · submit.html(reports·error reports) · mypage.html(saved·my reports) · admin.html(ops)
   site/assets/*.js ── common.js(api·saved·client token·Naver Map)
   │ /api/*
 ┌─▼──── Cloudflare Pages function functions/api/[[path]].js → server/app.js ──────────────┐
 │ routes.js route table → cafes.js(cafes·reports·notice) · errorReports.js · csv.js · admin.js(lock) │
 │ shared.js(JSON·cookies·text tidying) · geocode.js(Kakao lookups) · health.js(pin vs Kakao) │
 └──────┬─────────────────────────────────────────────────────────────────────────────────┘
        │ D1(schema.sql, migrations/ by hand only)

 owner's Mac, launchd 09:10 daily: scripts/admin-watch.mjs
   read-only D1 SELECTs (new queue items) + /api/data + health.js (pin vs Kakao) → Ohamma hub push → phone
```

### server/geocode.js

Address and place lookups on Kakao Local; callers pass the REST key (Pages secret `KAKAO_REST_KEY`, `~/.config/secrets/kakao-rest-key` on the owner's Mac). Used by the Pages functions (address search only — user-typed names never go to Kakao) and scripts/admin-watch.mjs.

- const `GEOCODE_TIMEOUT_MS` = 4000 — give up on the geocoder after this (a report waits at most this long)
- const `GEOCODE_QUERY_MAX` = 80 — longest search text
- function `searchQuery` — address → search text (drop notes in brackets, floor/room tails; join "로 48길")
- const `PLACE_RADIUS_M` = 300 — a listed place this close to the address point is the cafe
- function `sameName` — same cafe name (spaces/punctuation ignored, containment, or bigram overlap ≥ NAME_OVERLAP_MIN 0.5)
- function `kakaoSearch` — one Kakao Local search (address or keyword); HTTP errors throw
- function `geocodeAddress` — the single address hit {lat, lng, label} or null; network/timeout/HTTP errors throw
- function `findPlace` — the listed place named like the cafe within PLACE_RADIUS_M, or null
- function `districts` — the …시/군/구 words of an address
- function `matchesDistrict` — does a hit's label name one of the address's districts (else ambiguous)

### server/health.js

- const `FAR_M` = 100 — stored coordinates this far from the Kakao place (else address) are flagged (11/18, all 128: median 5 m, p95 24 m, then 149 m)
- const `EARTH_RADIUS_M` = 6371000 — haversine
- function `haversineM` — distance between two coordinates in metres
- function `rangeProblem` — lat = lng, outside South Korea, or no coordinates
- function `distanceProblem` — stored vs Kakao farther than FAR_M
- function `lookUpCafe` — Kakao address point, then the same-name listing near it (or near the pin); Kakao errors throw
- function `problemsOf` — every mismatch text + pinOff (the pin itself is wrong)
- function `checkCafe` — /cafe-check: {problems, pinOff, kakao}

### scripts/admin-watch.mjs

Daily admin watch on the owner's Mac (launchd `com.oakermann.kohee-watch`, 09:10, log `~/Library/Logs/kohee-watch.log`). Read-only: D1 SELECTs via wrangler and the public `/api/data`; the pin checks come from server/health.js. Pushes only new things through the Ohamma hub (`127.0.0.1:4096/notify`, same as blueprint-check). State in `~/Library/Application Support/kohee-watch/`. `--dry-run` prints the push, leaves state alone. Exit 0 ok · 1 a check failed · 2 push failed.

- const `MISSING_RUNS` = 2 — runs in a row not found on Kakao before "closed?"
- const `PUSH_NAMES_MAX` = 5 — names per push line
- const `HUB_TIMEOUT_MS` = 5000 — hub push timeout
- const `WRANGLER_TIMEOUT_MS` = 60000 — D1 query timeout
- function `nextMissing` — not-found streaks per cafe (failed lookups keep the old count)
- function `queueNews` — queue rows not seen last run
- function `queueLines` — push lines for new queue rows (user reports and error reports = counts only)
- function `nameList` — names, at most PUSH_NAMES_MAX
- function `freshFindings` — findings not pushed before
- function `prunePushed` — keep pushed keys of cafes still public
- function `findingsOf` — range, distance and missing findings
- function `buildMessage` — hub payload {title, text} or null
- function `readJsonFile` — read JSON (missing file = fallback)
- function `readKakaoKey` — the REST key from the secrets file (never logged)
- function `readQueues` — read-only D1 SELECTs: candidate ids and names, report ids, open error report ids
- function `fetchPublicCafes` — public /api/data
- function `lookUp` — health.js lookUpCafe for one cafe; errors = failed
- function `push` — POST to the hub (watch.sh's request)
- function `checkQueues` — new queue items (first run = baseline line)
- function `logSweep` — log counts, distances, flags
- function `checkHealth` — every public cafe; all lookups failing = an error
- function `main` — run both checks, push, save state
